# 当前胜率模型：13 场独立检验冻结方案

> 2026-10-14，在生成或查看本批模型预测及指标前确定。用户明确选择“13 场全部盲测当前模型”。这是 [M2 协议 v1](win-prediction-experiment-protocol-v1.md) 的既有模型检验分支，不是新候选的开发与采用实验。

## 固定对象与用途

- 唯一待检验模型：`win-baseline-v4-holdout-87-8-20260908` 中的 `baseline.joblib`，逻辑回归＋Sigmoid；SHA-256 为 `42f198ad900a17fa6f7deaaba44d80e25e155f65142c4e5d41da28b83fb4b760`。同时绑定模型清单、特征清单、推理样例及旧报告。
- 用户提供的 13 份 Mirage Demo 全部作为本轮测试，场次成员在本地冻结清单逐一绑定 SHA-256；不根据模型表现删场、换场或拆出开发集。
- 来源对应 ESL Pro League Season 24，比赛日期 2026-10-04 至 2026-10-11。登记逐场 HLTV 比赛标识、地图序号及公开比赛日期；头信息登记实际游戏补丁版本。来源核对以[赛事记录](https://www.hltv.org/results?event=8244)及各比赛页面为依据，不将文件修改时间当作比赛时间。
- 比赛日期采用来源页面的日期精度，未知的准确 UTC 开赛时刻保持空值。用于时间隔离的保守 UTC 外包窗口固定为 `[2026-10-03T00:00:00Z, 2026-10-13T00:00:00Z)`，覆盖已知比赛日期；不是声称所有日期边界都是实际开赛时刻。
- 旧 87 场输入和 79/8 成员保持原样。模型清单必须与旧数据、导出清单和审计文件哈希一致；87 场已在 2026-09-08 完成导出，是本次时间隔离的历史证据。旧比赛逐场准确日期和来源标识未全部补齐，因此不能宣称已完成 v1 的完整元数据登记或其跨来源身份审计。

## 推理、比较与统计

1. 使用现有 schema v4 / `mirage-semantics-v4.2` 导出与审计规则。全部 Demo 哈希不同于旧数据；公开来源比赛标识在新 13 场内唯一，地图序号及总回合数与来源交叉核对。解析失败或身份冲突必须报告，不能悄悄排除。
2. 推理复用 `WinModelRuntime` 的模型哈希、特征类型、未来标签拒绝及固定样例自检；仅传入地图、回合编号和当前特征，不将标签和权重传入模型。分批推理固定每批 256 点。
3. 仅使用旧 79 场训练分区拟合原 M2 工具中的固定 T 胜率基线及人数／装备四特征逻辑回归。旧 8 场及新 13 场均不参与拟合；两个诊断基线不作为本轮候选供选择。
4. 主指标是原回合权重下的 Log Loss；同时报告 Brier、AUC、准确率、ECE-10、预测覆盖率、导出覆盖率、逐比赛结果和可靠性图。原回合权重不因切片或缺失重新归一化。
5. 复用 `win_evaluation.py` 的固定分组：开局前 5 秒、5v5、live、下包后、总存活 ≤ 6、1vN、1v1、1v多人、装备价值差、装备／位置缺失和炸弹剩余时间。手枪局仍标为缺少已验证元数据。
6. 使用完整比赛为单位进行 2,000 次 bootstrap，seed 42、95% percentile 区间。整体与关键场景报告 Log Loss/Brier 区间，并对同一批时点和权重计算诊断基线减当前模型的配对差值。
7. 旧 8 场报告只提供历史背景，不能用新旧集合的分数差宣称模型改进。13 场同一赛事、重复参赛队伍的区间不能代表跨赛事或所有未来比赛的不确定性。

## 与候选实验的边界

本轮没有新模型、开发集、调参、重新校准、采用决策或默认模型切换。因此不伪造 `selectionPartition="development"`，不填写任意采用容忍度来套用 v1 的候选冻结入口。使用独立的 `existing-baseline-blind-v1` 本地执行清单，记录本方案、输入、模型、依赖、源码与实际构建文件哈希；评估前必须全部回读匹配。

本轮成绩公开后，这 13 场标记为已观察。它们可用于以后诊断，不能再次声称是 M3/M4 候选的未观察最终测试。后续新模型实验仍需按 v1 补齐登记、冻结开发／最终测试用途和采用门槛，并另留未观察比赛。
