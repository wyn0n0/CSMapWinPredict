# Mirage 回合胜率预测改进方案

> 编写日期：2026-10-12；状态更新：2026-10-22。M1、M2 既有模型的 13 场盲测、M3 第一批工程验证、M4 20 候选及 22 候选空间拆组完成。新增 C4 状态／距离固定对照仅使用原 79 场训练内验证，旧 8 场和已观察 13 场不评分；全回合后续优先 B 状态组，C 保留为广义残局候选。默认模型未切换。M5 推理事件补点、M6 基础曲线及事件段前后对比已完成，见第 8、9 节；M5 混合训练权重与准确率实验、完整来源登记、采用门槛及新候选最终盲测仍待安排，烟／闪／火细分、导航及模型贡献解释尚未实施。第 2 节仍为历史基线，后续模型结果见第 7 节。

## 1. 目标与范围

本方案改善 Mirage Demo 回放中的当前回合胜率预测，重点是：让显示结果只使用当前时刻可获得的信息；更可靠地衡量模型在新比赛中的表现；用更有意义的空间、装备与事件信息改善预测；让胜率变化成为可理解的复盘线索。

实施顺序建议为：**时间一致性修正 → 独立评估与基线冻结 → 特征对照实验 → 采样改进 → 复盘展示扩展**。模型复杂度由实验结果决定，优先沿用现有逻辑回归、LightGBM、校准与推理链路。

范围保持为 Mirage、当前回合胜方、Demo 回放中的局势估计。输入来自 Demo 可观察到的双方状态，不能解释为某一玩家视角所掌握的信息。多地图、真正的直播输入、整图/整场胜负预测，以及局势解说模型不在本方案的首轮范围内。

本文是候选改进路线，不改变项目当前局势解说工作的主线排期。实际实施可按模块分别安排。

### 2.2 既有留出验证结果

| 场景 | Log Loss ↓ | 加权准确率 ↑ |
| --- | ---: | ---: |
| 全部有效时点 | 0.4682 | 76.9% |
| 开局前 5 秒 | 0.5971 | 65.4% |
| 双方均为 5 人 | 0.5847 | 69.1% |
| 下包后 | 0.1873 | 92.9% |

总体 Brier Score 为 0.1585，ROC AUC 为 0.8423，ECE-10 为 0.0381。这些指标按既有回合权重计算；各场景可以重叠，不能相加。时点准确率不能解释为“开局即可预测对 77% 的回合”。

开局和 5v5 的误差更高，是后续重点观察的场景；后期局势本身更明确，阶段间难度差异不能直接归因于实现缺陷。

术语简释：Log Loss 和 Brier 衡量概率预测误差，越低越好；AUC 衡量区分胜负的能力，越高越好；校准检查“预测约 70% 的局势是否实际约有七成获胜”。ECE 是按概率分桶汇总的校准误差，不是每一次预测的误差范围。折外预测（OOF）指用未参与某次训练的比赛生成预测。

## 4. M1：预测显示的时间一致性

### 实施前已核验现状

修改前，[winPredictionAt](../../apps/web/src/domain/timeline.ts) 在同一回合、区段、阶段的相邻预测点之间进行线性插值。旧测试要求：10 秒为 40%、11 秒为 60% 时，10.5 秒显示 50%；本轮已将此行为及[测试](../../apps/web/src/domain/timeline.test.ts)改为显示 40%。

因此，若两点之间发生击杀，后一个预测点包含了击杀后的信息，击杀之前的显示也可能被改变。这是从代码推导出的展示时间问题，不等于已经证明训练特征泄漏；上述击杀时间是用于说明的构造例子，不是真实 Demo 复现记录。

### 改进内容

1. 当前时刻显示最近一个 `prediction.timeSeconds <= currentTime` 的有效预测点。
2. 保留阶段检查、过期检查，以及窗口边界、回合和区段隔离；核对调用链是否需要显式传入当前回合身份。
3. 概率数值不再通过未来预测点插值。若保留视觉过渡，过渡目标也必须是当前已到达的预测点。
4. 事件采样接入前，允许显示最近一次值并标明采样时间；不通过提前使用未来值掩盖采样延迟。

### 涉及位置

- [胜率取值逻辑](../../apps/web/src/domain/timeline.ts)
- [前端领域测试](../../apps/web/src/domain/timeline.test.ts)
- [页面调用](../../apps/web/src/App.vue)和[胜率卡片](../../apps/web/src/components/WinProbabilityCard.vue)

### 验收标准

- 修改任意未来预测点，不影响此前时刻显示的概率。
- 回放游标到达事件之后，才允许显示含该事件信息的预测。
- 拖动回放、跨窗口、冻结期、阶段切换、预测缺失和过期仍表现正确。
- 通过 `npm run typecheck` 与 `npm run test:web` 中对应检查。

本模块优先修正显示语义，不需要为了实施它重训模型。

### 实施结果（2026-10-12）

- 复用已有二分查找，返回最近一个不晚于回放游标的预测点，保留原始 tick、采样时间和概率。继续要求同阶段且不超过 1.5 秒；恰好到达采样时刻立即使用该点。
- 页面按当前游标查找最近的 `round-start` / `round-live` / `round-end` 事件，将其 tick 显式传给取值函数，拒绝更早的预测。上游回合重开有 start 边界，比分回滚在 live 信号处切换语义区段；由此隔离回合尝试和区段。未使用旧回放编号与模型语义编号直接比较，因为两者可能不同；不扩展 API 协议，也不根据未来预测推断当前身份。
- 当前窗口编号必须与游标所需窗口一致；导入、窗口待载入或载入失败时不沿用旧窗口预测。重叠窗口可提供当前时刻以前的采样点。
- 卡片显示实际采样时间，状态文案改为“按采样更新”，辅助阅读标签包含时间；移除概率条宽度过渡，使倒退拖动后的条形与数字同步。
- 开工前核查了 [pandas backward as-of](https://pandas.pydata.org/docs/reference/api/pandas.merge_asof.html) 的向后匹配、分组与过期限制，以及 [D3 bisector.right](https://d3js.org/d3-array/bisect) 的二分查找。仓库已有所需查找能力，直接复用；未复制第三方源码、新增依赖或另建插值器。

验收通过：`npm run typecheck`、`npm run test:web`（4 个文件、31 项测试）及 `npm run build`。领域测试覆盖未来点修改/追加/删除不改变过去、到点更新、倒退、阶段、缺失、过期、同编号重开、区段和重叠窗口；[页面渲染测试](../../apps/web/src/App.test.ts)覆盖边界事件接线、采样时间、窗口等待/失败、导入和示例来源标识。未重新解析真实 Demo 或训练模型；不将构造事件用例描述为真实比赛复现。

## 5. M2：数据、评估与概率校准

### 已核验现状

当前已按比赛隔离训练和验证，没有使用时点随机切分。主要限制是留出验证只有 8 场，且结果已经被观察；后续反复据此调参，会降低其作为独立评估的价值。

实施前存在分组口径差异：[评估脚本](../../tools/train_win_baseline_v4.py) 的 `clutch` 使用 `totalAlive <= 6`，包括 3v3、2v4；[特征构建器](../../apps/api/Features/WinPrediction/AsOfTickFeatureBuilder.cs) 的 `IsClutch` 使用“一方剩余 1 人”。10 月 12 日先修正评估命名与分组，保留现有模型特征契约；10 月 15 日用户确认的广义残局定义见下文更新。

### 改进内容

1. 保留现有 79/8 切分和报告用于复现；登记新比赛的日期、赛事、游戏版本、地图、Demo 哈希及解析版本，并检查重复。
2. 新实验预先冻结训练、开发评估和最终测试用途。保留时间更晚、未用于选择方案的完整比赛作为最终测试；比赛数量和时间窗口在查看测试结果前确定。
3. 保持按完整比赛分组；数据足够时增加按赛事留出的敏感性检查。不要把相邻时点当成独立样本随机分组。
4. 当前主残局分组采用双方均有人存活、合计 ≤ 7 的广义残局（10 月 15 日确认，完整前提见下文）。原“总存活人数不超过 6”保留历史名称；1vN、1v1、1v多人仍独立报告，避免与广义残局或 0vN 混同。
5. 在现有开局、5v5、live、post-plant 切片上，逐步加入经济差、手枪局、1vN、装备缺失、位置缺失和下包后时间段。新增分组所需元数据必须可追溯。
6. 同时报告预测点数、回合数、比赛数、样本权重和不输出预测的覆盖率。单一胜负类别的分组仍可报告适用指标；AUC 标为不可计算，不静默丢弃整个分组。
7. 用比赛作为重采样单位估计指标及候选模型差值的区间。8 场旧验证集的区间只能作小样本诊断，不能把大量时点当作扩大后的独立样本量。
8. 增加仅使用训练数据估计的固定 T 胜率基线，以及少量人数/经济特征基线，检查复杂特征是否带来稳定收益。
9. 校准器仅在训练/开发流程内拟合与选择，最终测试不参与校准。继续比较不校准、Sigmoid 和 Isotonic；额外报告可靠性图及关键分组校准情况，暂不因少量分组样本就建立独立校准器。

### 产出与验收

- 一份冻结的实验协议：数据来源、分组键、切分、主指标、关键场景、候选方案和测试使用规则。
- 一份可追溯评估报告：整体、分场景、逐比赛、校准、覆盖率、指标差值区间。
- 同一比赛和重复 Demo 不跨训练/测试；校准和模型选择不读取最终测试结果。
- 验证 1v1、1v3、3v3、0v3 的分组；单类别小分组不导致评估崩溃或被整体遗漏。
- 优先验证 `npm run test:train:v4`；涉及数据审计约束时加 `npm run test:audit`。

## 6. M3：空间与炸弹相关特征

### 已核验现状

[AsOfTickFeatureBuilder](../../apps/api/Features/WinPrediction/AsOfTickFeatureBuilder.cs) 用归一化 X/Y 坐标计算站位分散程度、最近敌人距离、到固定 A/B 点的距离。该计算不能表示墙体阻隔、实际绕路、楼层或单向落差。

当前获选模型未直接使用完整玩家数组和区域数组；它们在[样本构建器](../../apps/api/Features/WinPrediction/WinFeatureSampleBuilder.cs) 中被移除。应增加有明确意义的聚合量，而不是直接把所有玩家字段都塞入模型。

### 第一批：利用已能确认的当前状态

2026-10-14 已实现独立 `win-spatial-v1` 伴随导出，3 路并发验证旧训练分区 3 场、78 回合、7,309 点；原 v4 样本全部一致。见[实施记录](win-spatial-m3-first-batch-20261014.md)与[验证报告](../win-spatial-m3-report-20261014.md)。本次只验证工程正确性，半径来自训练集初始几何尺度；模型收益和参数选择留待 M4，不代表下面全部模型/导航验收完成。

- 双方到实际 C4 位置的最小距离、次近距离及其差值；区分携带、掉落和已下包。
- 携包人与最近队友的距离、携包人附近队友人数，作为孤立程度的候选描述。
- 经过定义和核验的包点邻近人数、队友接应距离；距离阈值只能按训练/开发集确定。
- 显式保留坐标未知、不适用及有效人数，避免用 0 冒充缺失距离。

这些仍是空间近似值，不能直接称为“控制某区域”或“能及时回防”。第一批优先用现有字段验证新增聚合是否有收益。

### 第二批：经过核验的导航与可达性

- 对照 CS2 地图版本，引入导航区域、方向性连接、楼层定位和可达路径。
- 计算到包点及实际 C4 的路径长度，作为直线距离的补充或替代候选。
- 在移动耗时估计得到验证后，试验“爆炸剩余时间 − 到包耗时 − 拆包耗时”等时间余量特征；必须考虑拆包工具、是否已经拆包等当前状态。
- 地图控制、视线、烟雾和火焰影响留作后续增量，每一组单独比较收益与成本。

可参考 [Awpy 导航网格](https://awpy.readthedocs.io/en/stable/nav.html)、[地图控制](https://awpy.readthedocs.io/en/stable/map_control.html)与 [WPA 的图距离方法](https://arxiv.org/html/2011.01324v2)。优先检查仓库已有空间能力是否可复用；新增依赖和资源前核对格式、来源、许可与版本，不替换整个解析链路。

### 验收标准

- 用人工可核对的位置验证隔墙、绕路、上下层和单向落差；未知/不可达与零距离分开。
- 同一 tick 的特征不受未来位置、未来炸弹状态或最终胜负影响。
- 对当前基线分别增加第一批、第二批特征，以相同切分和采样比较 Log Loss、Brier、校准和关键场景表现。
- 记录导出及推理耗时；路径估计未经验证时，不将其用于强制输出 0%/100%。
- 特征契约发生变化时使用匹配的新数据与模型包；执行对应语义、审计、训练及推理检查。

### 已核验现状

既有留出集上，校准逻辑回归的 Log Loss 为 0.46816，校准 LightGBM 为 0.46849。差距很小，尚不能据此确认算法层面的稳定优势。

现有输入包含双方总量、差值、比分、回合数及存活玩家累计击杀/死亡统计。模型报告中的 `features.ct.totalDeaths` 在逻辑回归系数绝对值排序中居前，值得做删减实验；相关特征会分摊或改变系数，不能把该排序直接解释为真实贡献或泄漏证据。

### 对照实验设计

先固定数据、切分、采样、权重和校准流程，一次改变一个特征组。下表是实验设计，不是已完成结果。

| 实验 | 输入变化 | 要回答的问题 |
| --- | --- | --- |
| E0 | 重现现有 98 字段基线 | 新实验环境是否可复现原流程 |
| E1 | 人数、血量、装备、时钟、炸弹状态的小特征集 | 简单输入能达到什么水平 |
| E2 | 在 E1 上加入现有空间聚合 | 现有空间信息是否稳定有效 |
| E3 | 在固定对照上加入 M3 第一批 C4/队形特征 | 新信息是否改善开局、回防或残局 |
| E4 | 对固定对照移除累计击杀/死亡；再独立移除比分/回合进度 | 这些上下文信息改善泛化，还是依赖特定比赛分布 |
| E5 | 独立试验武器类别、烟/闪/火数量等更细装备信息 | 细分资源是否优于总价值和总数量 |
| E6 | 独立加入经过核验的导航特征 | 路径信息是否值得额外计算成本 |

E0 在新比赛上仍需重新评估，历史分数不能直接填入新测试报告。E4 的上下文特征本身不是当然错误，应由结果决定是否保留。E5 先核验上游字段的可用性、语义和缺失比例。

### 模型策略

1. 沿用现有逻辑回归与 LightGBM，先试少量正则化、树深和叶节点设置。若新增早停，只能使用训练内部或开发数据。
2. 对逻辑回归试验少量有明确含义的交互项，例如阶段与人数差、爆炸剩余时间与拆包工具状态；每组单独验收。
3. 有限数据下优先使用统一模型和阶段特征；是否拆成开局/下包后模型，取决于分阶段数据量与验证收益。
4. 神经网络、图网络或更长时序模型留到现有特征路线出现可重复的瓶颈后再评估。
5. 解释按人数、血量、装备、时钟、空间等组组织。预测概率变化与模型解释贡献分开，避免把回归系数直接写成“胜率增加若干百分点”。

### 候选模型采用条件

- 模型选择只看预定的训练/开发评估；最终测试用于一次性检验已冻结候选。
- 主指标为预先约定的加权 Log Loss，同时观察 Brier、校准、覆盖率和关键场景。
- 在观察最终测试前，冻结可接受退化幅度、计算预算和采用条件；本方案不预设未经依据的提升百分比。
- 若差值区间包含明显退化可能，或关键场景表现不稳定，保留现有默认模型并记录实验结果。
- 模型、校准器、特征清单、依赖、切分、报告及推理样例必须匹配。

## 8. M5：事件采样与样本权重

### 已核验现状

[WinFeatureSampleBuilder](../../apps/api/Features/WinPrediction/WinFeatureSampleBuilder.cs) 继续按约一秒间隔选择基准／训练样本。2026-10-22 起，[事件补点](../../apps/api/Features/WinPrediction/WinEventSampleBuilder.cs)在生产推理中加入确认后的关键状态；基础间隔和混合采样模式分别声明。旧数据不会自动补算。

### 改进内容

1. 保留每秒采样，增加击杀、下包、开始拆包、取消拆包等关键事件之后的可确认状态点。
2. 核验现有时间线的状态分辨率。若事件 tick 没有对应的可信快照，先补充事件状态采集；不得用稍后快照冒充事件发生时的状态。
3. 对同 tick 的事件和定时样本去重，记录采样触发类型及真实状态 tick；先完成同 tick 状态更新，再构建预测输入。
4. 保持回合终点与已结算结果隔离，不把最终胜负作为普通输入或通过回合结束采样直接泄漏标签。
5. 比较“仅定时采样”和“定时＋事件采样”，此轮保持模型和特征不变。
6. 预先选择混合权重方案：例如回合内按定时/事件两类分配固定权重预算，再分别归一化。仅保证回合总权重为 1，仍不能避免事件密集阶段被过度强调。
7. 固定定时评估面用于前后可比的主指标，事件评估面单独报告响应延迟与误差。两者都保持相同的比赛隔离。
8. 检查 API 采样元数据、前端过期判断和窗口边界能否准确表达不规则间隔。

混合采样可参考 [2026 年 CS2 回合预测研究](https://vskp.vse.cz/100656)，其数据分布和权重口径不能直接替代本项目设计。

### 验收标准

- 关键事件能产生对应状态的预测，且 M1 的“未来不影响过去”检查仍通过。
- 无重复样本键，无跨回合、作废尝试或未来装备状态污染。
- 权重方案、样本构成、定时与事件评估结果完整记录。
- 实测导出体积、推理批次数、导入耗时；主指标比较不混用新旧采样分布。

### 推理补点实施结果（2026-10-22）

- 生产导入显式采集独立事件状态，保持旧帧、装备历史及语义采样不变。击杀／下包使用游戏事件；拆包开始／取消逐 command 观察 C4 复制状态的转换，真实 GOTV 存在缺少对应通知的情况。
- 同 tick 最后一次 command 覆盖之前状态，之后才构造特征。死亡、下包、点包、松手各自校验状态是否吻合；不能确认时不使用稍后状态冒充。回合结束与拆除／爆炸不新增预测。
- 原每秒点保留；额外点用原 8 Hz 历史加当前事件状态，不让新增点改写既有 C4 历史特征。事件前补算取同回合且距首事件 ≤0.125 秒的已有快照，只存入复盘比较，不进入实时窗口或曲线。
- 记录 regular／event-before／event-after 触发角色、真实 tick、事件组及采样模式；同 tick 去重，雷达窗口加入事件帧，以便下包／点包时同步显示。原模型和训练导出、权重均不变。
- 真实 9z–FaZe 开发回归覆盖至 tick 248000：原 2606 个定时点特征、常规帧、装备和语义完全一致；在真实取消拆包 tick 134956 截断，此前事件状态仍一致。5 次开始拆包、2 次取消均得到对应预测；其中一次点包仅持续 10 tick（0.15625 秒）。
- 整场真实导入生成 2932 个基准点、3139 个曲线点，连同事件前补算共 3314 次预测，比基准增加约 13.0%；复盘 Brotli 文件 105192 字节。单次本地解析 14.62 秒、导入总计 19.13 秒，不含文件选择／上传；这些是开发诊断，不是稳定性能基准或准确率改善证明。

混合采样训练、权重预算、固定定时面与事件面的误差对照仍未执行；不能将本轮推理补点等同 M5 全部实验完成。详细验证见[完成记录](../context/history/2026-10.md#2026-10-22m5-关键事件补点与-m6-前后对比)。

## 11. 数据与模型版本边界

- 旧数据集、79/8 切分、历史模型与报告保留用于复现，不覆盖或回写历史指标。
- 新导出和新训练使用不存在的新目录，记录输入哈希、源码版本、依赖、seed、切分、特征和采样/权重方案。
- 特征语义或协议变化时明确新版本，提供匹配的导出、审计、训练与推理路径；不能只修改版本数字宣称兼容。
- 实验模型先独立加载和评估，通过既定条件后再考虑默认模型切换；模型不可用仍不应阻断 Demo 回放。
- 原始 Demo、模型、训练数据及本地设备路径不写入公开发布材料。代码提交、模型上传和远端部署不属于本文的执行内容。
