# M3 第一批：C4 与队形特征实施记录

> 2026-10-14；用户确认范围：第一批实现、定向测试、小规模真实数据验证。导航只列前置条件。模型效果比较和采用决策留给 M4。执行结果见[验证报告](../win-spatial-m3-report-20261014.md)。

## 范围与版本

新增 `win-spatial-v1` 实验伴随文件，由 `WinSpatialFeatureBuilder` 读取**单个原始回放帧及同 tick 的语义名单质量**。不读取下一帧、未来炸弹状态或回合胜负，不改变现有 `WinFeatureSampleBuilder`、v4 默认模型、API 推理或前端。

独立 CLI `--export-win-spatial <demo-or-directory> <new-output> <support-radius> <site-radius>`：

- `base/`：沿用原 v4 导出函数的样本、manifest、逐场 audit。
- `spatial.jsonl`：独立 `contractVersion=win-spatial-v1`，仅包含键和新增特征，不携带标签、权重或玩家身份。
- `source.jsonl`：同键的当前原始坐标、C4 状态及名单质量，供独立重算；身份仅留在审计证据，不进入特征。
- `manifest.json`：完成标记、基础版本、两个半径、A/B 参考点、距离定义、全部输出哈希、行数和分段耗时。

连接键为 `matchId + roundId + tick`，同时核对 `segmentId / roundNumber / mapName`。样本筛选和回合等权重完全复用 v4。新文件不能冒充 schema 4 的输入，也不直接送入旧推理服务。M4 接入时需显式实现版本检查、连接、特征清单、训练和推理一致性检查，并生成新模型包。

## 第一批特征定义

全部距离为世界坐标 X/Y 的欧氏直线距离，计算前要求 X/Y/Z 有限。没有路径、楼层、视线、移动速度或到达时间含义。

| 组 | 字段与含义 |
| --- | --- |
| C4 | 原始 `bombState`；carried/planting/dropped/planted/defusing 使用当时实际 C4 坐标；双方最近、次近距离和 T−CT 差；携包人本人参加 T 到 C4 排序，故最近距离可以为真实的 0 |
| 携包人 | carried/planting 时仅匹配当前存活 T 携包人；排除本人，计算最近队友距离和距离 ≤ 支援半径的队友数 |
| 包点邻近 | 每队到固定 A/B 参考点距离 ≤ 包点半径的存活人数；A=(-378.01,-2102.56)，B=(-1942.49,356.14)，复用 `MapFeatureGeometry`；圆形邻近范围不等于实际包区边界 |
| 队形接应 | 对每个存活玩家求最近存活同队队友距离，再取团队均值和最大值；不将其描述为实际可支援或控制区域 |
| 质量 | 名单完整性、每队观测存活人数、有效坐标人数、可计算 C4 距离人数、携包人队友人数和有效坐标人数 |

缺失规则：

1. 名单未知、生命状态不齐、观测存活总数与语义人数冲突或重复身份：全队聚合置空，保留观测计数用于诊断。
2. 某队坐标缺失时，该队的距离、计数和接应聚合置空，不能把剩余子集当成完整团队；另一队完整时可继续计算。语义与实际有效坐标总数冲突则两队均置空。
3. C4 坐标缺失、携带态找不到存活 T 携包人时，C4 距离置空。终局为 `not-applicable`，unavailable/未识别状态为 `unknown-state`；均不沿用残留坐标。
4. 单人队伍没有次近 C4 和队友距离；空队伍的距离为空，确认完整时邻近人数为 0；真实重合位置的距离保留 0。
5. 无队友携包人：`no-teammates`、邻近人数 0、最近距离 null；掉落/下包时携包人组为 `not-applicable`、数值 null。

## 半径与小规模验证

不按 13 场已揭盲比赛或旧 8 场验证集选阈值。此次工程探针从旧 79 场训练数据计算两个几何尺度，输入与切分哈希保存在本地 `pilot-plan.json`：

- 支援半径 **861.320**：T/CT 合并、至少 2 名存活时的站位离散度，按原回合权重取加权中位数。
- 包点半径 **582.716**：T/CT 合并的最近包点距离，按原回合权重取加权中位数。
- 原 v4 距离乘 5120 还原世界单位；取 3 位小数。在新导出前冻结。它们是训练数据给出的初始尺度，不代表经效果验证的孤立/支援或包点控制阈值。M4 只能按 train/dev 调整，并保持所有对照使用同一配置。

真实探针取旧训练分区按文件名排序的前 3 场：9z–FaZe、9z–PARIVISION、Astralis–MOUZ。先核对 Demo SHA-256 与旧 manifest；三个独立进程同时导出，各写新的 shard 目录。使用 `tools/audit_win_spatial.py` 核对哈希、连接、逐回合权重，并从原始证据独立重算每个新增字段。另与旧 v4 样本逐行比较，验证基础特征、标签及权重没有改变。

定向验收覆盖数值可手算场景、半径边界、状态切换、缺失值、身份/顺序不变性、未来位置/炸弹/胜负变更、版本及键对齐。真实 Demo 再运行“完整解析与截止 tick 解析”对比。该轮只验证特征正确性及导出成本，**没有训练新模型或证明预测收益**。
