# 阶段六解说评价协议 v1

协议标识为 `stage6-commentary-20261005-v1`。机器可读权威文件为[协议配置](../situation-implementation/situation-commentary-protocol-v1.json)、[提示词配置](../situation-implementation/situation-commentary-prompt-v1.json)和[通用规则](../situation-implementation/situation-commentary-rules-v1.json)。本说明解释其执行口径；实际冻结哈希、诊断清单和长度结果见[步骤四报告](../situation-implementation/stage6-commentary-protocol-report-20261005.md)。旧 Facts-only/2560 协议及历史结果保持独立。

## 任务与对照

输入为同一配对记录的完整 Facts 和已选核心 Scene；核心字段、精度、null/unknown、质量标记全部保留。输出仍为 `situation-narrative-v1`：highlights 2–4 项，summaryZh 最多 240 字符，目标 2–3 句、约 80–180 汉字。长度目标不是要求在信息不足时补造内容。只解释当前已知局势、依据关系及限制，不推测意图、未来结果或胜率，不提供战术指令。

| 对照 | 内容 | 用途 |
| --- | --- | --- |
| B0 | 同版本 `SituationTemplateNarrator.Create(Facts)`，固定 v8 规则 | 确定性参照与回退；只消费 Facts，不计模型成功 |
| A / B1 | 已准入核心输入摘要 prompt，加共同格式与解释边界 | 未微调摘要对照 |
| B | A 的共同条件上强调重点、因素关系和具体限制 | 解释风格候选 |
| C | B 加一条独立合成教学示例 | 示例事实与 `ex.*` ID 不得进入当前回答 |
| D | B 加 CPU 确定性内容计划 | 模型只调用一次；计划不是第二个模型输出 |
| B2 | A–D 完成后，仅按 dev 结果选择 | 训练前冻结准确组别、所有绑定及选择理由 |

A–D 的核心 payload 完全一致。共同规则是对已有观察的解释限制，不能成为新增现场事实。D 的计划含 focus、supportedClaims、evidenceIds、ruleIds、limitations，最多两条主张、两条限制；优先人数/空间冲突、下包、接触风险、人数。Scene 直接观测另用 `scene:` 引用，不能冒充旧 Facts evidence ID。Python CPU 参考实现用于本轮预算，后续执行入口须复用或证明同值一致，不能静默换成不同 planner。

固定 Qwen3-1.7B revision、NF4/double quant、BF16 compute、cuDNN SDPA、非 thinking、greedy、batch 1、512 新 tokens、两个 EOS ID、seed 42。显式关闭基座 generation_config 的采样参数继承。请求硬超时 60 秒、加载 600 秒；到长度上限视为截断失败，即使文本看似闭合。LoRA 与 B2 的输入、prompt、计划、规则、量化及解码完全相同，只改变 adapter。

## 样本与盲评

诊断固定 20 train、30 dev，dev 包含既有 7 条人工复核场景的配套输入；新增 23 条 dev 的实际输出仍须人工评价。选择只使用输入特征和稳定哈希，保留比赛、回合、来源/输入/原始行哈希。额外样本避免同回合和同来源场景重复，覆盖 5v5、残局、下包、人数/空间冲突、质量限制和未知信息。质量类别包括 low confidence 或 warning/error；unknown 类别包括核心观察中的 null/unknown，因此不代表罕见或困难程度相同。

原人工 approved 仅指旧标签。每组新输出均需新的盲评；协调者保管别名映射，评价者只看当前输入、支持规则和匿名输出，不看组别、adapter、epoch、耗时或原文件顺序。每条样本的候选顺序固定打乱，B/C/D 分别与 A 成对比较，允许平局和双方失败。空白表和 null 均表示 pending，不能算通过。自动支持检查与人工语义判断分开保存。

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 重点选择 | 无重点或重点错误 | 列出重要事实 | 说明当前核心态势 |
| 综合解释 | 只复述或推论错误 | 简单比较 | 合理联系依据并解释意义 |
| 通俗程度 | 工程术语堆积或难懂 | 基本能懂 | 普通观众能顺畅理解 |
| 不确定性 | 编造或过度断言 | 泛化地说不足 | 指明缺失条件及其影响 |

另行判断事实忠实、准确且有用、重大事实矛盾、明显臆测、禁止内容及新增不受支持事实。每次判定保留理由、逐条主张的支持记录、评价者和时间。语言流畅或复述率低不能抵消事实错误。当前 Scene 值引用可证明观察值，却不能自动证明包含因果、意图或胜负含义的中文句子。

输入盘点发现人数/空间冲突全 train 仅 1 条、dev 为 0 条。初始每类 train2/dev3 配额因此在 r1 失败；在未查看任何模型输出时改为先保留这条真实 train 场景，dev 该类配额为 0，其余类别仍为 train≥2/dev≥3。不能宣称 dev 覆盖了冲突情形，不能补入 test 或用合成场景冒充真实 dev。此变化只调整可实现的输入覆盖，不改变质量门槛。

## 合法性、修复与分母

原始合法要求运行完成并以固定 EOS 停止、严格单个 JSON（拒绝重复键、NaN 等非 JSON 值）、Narrative Schema 和字段约束均通过。原文、停止原因和错误必须保存。未知 evidence ID 另记为证据错误；一个存在的 ID 仍需核对其是否支持对应中文主张。Facts 是派生事实的权威，核心 Scene 只在选定范围提供补充观察。

只有非空、非截断、运行完成而格式或结构不合法的输出可尝试一次格式修复。修复 prompt 不带当前 Facts，也不供应可用 ID 清单，只允许修标点、转义、括号或明确的键格式；所有文本、数值、ID 及所属主张必须保留。不能可靠证明原内容与修复后内容一致时拒绝修复。缺失语义字段不能编补，未知 ID 或事实错误不能通过修复改写。超时、OOM、截断和运行异常不重试。保留原始/修复文本、独立检查结果和调用计数；模板回退另报。

每次修复前重新 tokenize 真实 raw output 和完整修复 prompt，原文最多 512 tokens，完整输入最多 4608；超限直接失败，不截断。静态压力夹具只验证已测输入，不能替代未来输出的动态预算与内容保留验证。统一只读评价器及格式修复内容检查须在步骤五生成前实现并测试。

所有已计划的原始请求都是分母，包括空输出、超时、OOM、截断、异常和不可确定的已派发请求。原始与至多一次修复后的视图分别报告，不能逐条择优拼表。非法或运行失败不算事实忠实；语义尚未审核不算通过。另报未知 ID、事实矛盾、新增不受支持事实三者的样本级并集及各分项，不让解析失败从忠实度分母消失。

## 门禁和选择

50 条汇总仅用于路线初筛：重大事实矛盾为 0，原始合法至少 48/50，候选成对优于 A 至少 30/50，通俗性平均分与准确有用率都提高。train20、dev30、原人工 dev7 分项保留。这不等于正式 98%/99.5% 门禁通过，也不说明统计显著。

B2 只用 dev30，排除禁止内容、重大事实矛盾及未完成审核的候选；依次比较修复后忠实率、准确有用率、量表总分、原始合法率，同分优先修复次数少，再按 A/B/C/D。若无合格候选则不冻结 B2、不训练。初筛的 train 汇总不能用于候选排名。

首轮 200 条训练小试最多一个训练 run、2 epochs，只在 epoch 末评价，最多 2 个 checkpoint 和 2 次 dev 评价；预期更新点 13、26，实际数据/累计步数不符须先重新登记预算。checkpoint 依次比较修复后忠实率、有用率、原始合法率和量表总分，同分选较早 epoch。扩大试验另立协议和预算，不能无限增加候选。

LoRA 相对冻结 B2 的主指标为原始合法率、至多一次修复后的忠实率、同口径人工准确有用率。相同样本及分母上三者均不得下降，至少一项提高 8 个百分点。先在 dev 选定唯一候选并冻结，再开启最终 test。若基线接近上限而无法达到增益，先记录上限问题，不降低门槛或改选较弱基线。

最终自动评价覆盖冻结的 8 场 test 全部记录；人工范围仍为原先冻结的 7 条。test 此前已经在规则验收中观察，不冒充外部盲测。比较 B0、A、B2 和唯一 adapter，A=B2 时复用同一结果。自动原始合法≥98%、修复后合法≥99.5%、证据/矛盾/新增事实错误并集≤2%；人工明显臆测≤5%、准确有用≥85%、禁止内容为 0。7 条人工意味着明显臆测须为 0、准确有用至少 6 条。一条约 14.29 个百分点，新增 dev30 不扩充旧 dev/test7。

报告分子/分母与 Wilson 95% 区间；差值以比赛为簇做固定 seed42、10000 次配对 bootstrap，并披露小样本、相关性及描述性局限。复述、证据复制、字符串重叠只作诊断。合法最小变化测试从独立合成 Scene 重建所有相关 Facts/evidence，分别改变人数和炸弹阶段，检查解释是否响应；不直接修改数字制造不一致输入，真实与合成结果分开。

最终 test 只执行一次；失败保留证据和模板回退，不据 test 换 adapter。基础设施恢复最多一次，必须校验全部绑定、保留原请求清单和原子终态。只恢复尚未派发的请求；已派发而结果不明记 indeterminate 失败，已完成或模型自身失败不得重跑。源码、配置或来源漂移须新建版本和目录。

## 长度与资源

全量 train/dev × A–D 逐条 tokenize 完整 system、教学示例、计划、引用规则、chat template 和生成前缀；输入加 512 必须≤5120。不截断、不删 Facts/核心字段、不丢弃超长记录。未来新标签另外测完整 assistant/EOS 总长≤5120、completion≤512；本步没有新标签，不能宣称新训练标签预算已通过。test 新 prompt 长度只在最终候选冻结后走隔离入口。

步骤五最多 10 条校准＋200 条 A–D 原始请求、最多 210 次格式修复，共 420 次模型调用、215040 输出 tokens；B0 50 次 CPU 请求单列。按每请求 60 秒计算的硬请求上限是 7 小时，另有 600 秒加载上限和 5 GiB 保存空间预算。这不是耗时预测；实际时延、TTFT、显存、健康余量须由步骤五校准。协议就绪与生成/训练资源就绪分别记录。
