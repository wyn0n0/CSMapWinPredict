# M4 特征与模型开发对照报告

> 2026-10-15。按用户确认的“79 场训练＋13 场已观察开发、旧 8 场保留诊断、不切换默认模型”范围完成。20 个候选、92 场空间导出、训练／推理配套及独立复算均完成。烟／闪／火细分、导航和最终盲测仍有前置条件；不将本轮写成 M4 所有后续分支或候选采用流程全部完成。

**结论：保留当前默认模型。** 开发集排名第一的是原 98 字段、31 叶／深度 7 的 LightGBM，Log Loss 为 **0.474738**，当前默认模型为 **0.483593**。二者配对差值为 **−0.008855**，95% 比赛重采样区间 **[−0.021025, +0.001538]**，仍包含退化可能；最优候选的整体、开局和 5v5 校准误差也更高。本轮没有独立的未观察测试集，不能据此确认稳定泛化优势。

执行前的固定规则、特征清单及命令见[开发方案](plans/win-m4-development-20261015.md)。它是用户确认的 M2 开发分支，不放宽原 M2 最终采用条件。

本轮取舍如下：

1. **原生产特征保持不变。** 没有证据支持因为系数大就认定累计击杀／死亡是泄漏；删除它们后的整体变化很小。删除比分／回合进度反而使 LightGBM 在本批开发比赛上退化，因此不统一删除这组输入。
2. **29 字段逻辑回归保留为简化候选。** 整体误差接近原模型、推理较快；但下包后和 1vN 的 Log Loss 分别为 0.25695、0.17912，高于默认的 0.24821、0.16416，不是无代价替代品。
3. **M3 空间保留为实验候选。** 逻辑回归的 1vN Log Loss 从 0.16416 降到 0.14070，差值 −0.02346，区间 [−0.03996, −0.00827]；这是值得独立验证的线索。整体、开局、5v5 和下包后的差值区间仍跨零；LightGBM 整体增益很小，不将新特征直接加进生产模型。
4. **本轮不因 E5 或交互项增加生产输入。** 武器类别子实验没有改善整体误差；两个交互项及逻辑回归正则化变化也没有稳定优势。最优树设置与原树设置的差值为 −0.002901，区间 [−0.009197, +0.003268]，不构成稳定参数优势的证明。

## 5. 版本、解释与计算成本

- 新包使用 `featureContract=win-m4-v1`；E3 显式绑定 `win-spatial-v1` 配置和哈希。生产 Python 入口拒绝实验契约，独立实验运行时校验清单、模型文件、特征、空间配置和推理样例。API 配置和默认模型未切换。
- 20 包分别独立加载并对全部开发点推理，**489,780 次候选预测与对应训练模型输出完全一致**。另用 CLI 对 E3 的 3 个样例验证，最大差 1.11×10⁻¹⁶。未来胜方、缺失契约、错误配置、损坏文件均有拒绝测试。
- 逻辑回归按人数、血量、装备、时钟／炸弹、空间、上下文等组汇总未校准的对数优势贡献。全部检查的最大重建误差为 1.24×10⁻¹⁴；不将回归系数或对数优势直接转换成“胜率增加百分点”。LightGBM 仅汇总训练分裂增益，不作因果解释。本轮没有向复盘界面加入模型贡献文字。
- 92 场导出和逐场审计墙钟约 **524.0 秒**，3 路并发；20 个候选的全部折内及最终拟合累计约 **324.3 秒**。结果记录从首个候选开始到完整统计报告约 **488.3 秒**，不含前置数据载入／重审计及最后文件写出。
- 表中推理耗时采用 256 点批次，包含输入校验、表格构建和预测；不包含解析、进程启动、样例字典准备及 JSON IO。它是本次一次运行的成本记录，不是在线延迟承诺或严格速度排名。
