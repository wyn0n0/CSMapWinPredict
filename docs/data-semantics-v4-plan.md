# v4 数据语义修正与迁移方案

更新日期：2026-08-31。状态：方案及上游核查已完成，解析器修复、v4 导出与重训尚未实施。当前代码仍使用训练 schema v3。

## 目标与边界

明确每条样本属于哪个正式回合、比赛实际进行到什么时刻、哪些状态已知。第一版继续限定 Mirage 当前回合 T/CT 胜率，不同时引入直播服务、新地图或复杂模型。

执行顺序：回合身份 → 时钟 → 阵容与字段完整性 → 全量重导出 → 固定条件重训比较。前两步可直接使用现有 demofile-net 0.44.1 接口，见 [上游核查](round-clock-upstream-review.md)。

## 1. 回合身份与正式编号

| 拟新增／明确的字段 | 语义 |
|---|---|
| roundId | 回合尝试唯一标识，用于关联状态与结果，不进入模型 |
| roundNumber | 经游戏规则与比分核对的正式回合号 |
| segmentId | 真实比赛重置或恢复区段，不能因每次普通 CsPreRestart 都增加 |
| phase | warmup、freeze、live、post-plant、ended 等阶段 |
| roundDisposition | 已完成、作废、结果缺失或待确认 |

新增 RoundStateTracker。RoundStart 只作为创建尝试的信号，正式回合号结合 RoundStartRoundNumber、TotalRoundsPlayed、阶段与开始比分确认。byte 类型的 Start/EndCount 用于检测变化，不作为永久编号。

同一 command 可同时出现开始与结束信号；应收集后结合规则快照确定各事件归属。CsPreRestart 在正常回合切换也触发，RoundOfficiallyEnded 在部分 Demo 不触发，二者都不能单独决定正式回合有效性。

回合结束后确认标签，作废与结果缺失的尝试不生成正式标签。允许使用后续结果确认标签资格，但禁止将未来状态回填为当时可见的输入特征。

验收：此前 4 场、87 个编号异常回合逐一归因，所有增删与重编号可追溯；不要求新数据机械保持旧回合总数。

## 2. 时间语义

| 拟定义的字段 | 语义 |
|---|---|
| demoTimeSeconds | 回放位置，仅作定位与审计 |
| liveElapsedSeconds | 有效 live 进度，冻结和暂停不应被错误累计 |
| roundRemainingSeconds | 下包前的有效回合倒计时 |
| bombRemainingSeconds | 下包后的爆炸倒计时 |
| defuseRemainingSeconds | 拆包进行中的剩余时间 |
| clockKnown / clockSource / pauseContext | 可信度、计算来源与暂停上下文 |

新增 RoundClockResolver。正常且可信的 live 状态优先核验 CurrentGameTime - RoundStartTime；不能把 Demo 时间与游戏时间混减。冻结期间 RoundStartTime 可在未来并持续调整，因此不能无条件使用该差值。

下包后区分原回合倒计时与 C4 时钟；不适用或未知的值使用明确标记，不静默填成 0 或默认 115 秒。已有 C4Blow 和 DefuseCountDown 可提供双截止时间。

暂停需要综合阶段与引擎时钟实际推进判断：战术 timeout 标志可能提前置位，不能简单对所有标志做 OR 后停表；也不能重复扣除已经反映在时间起点中的暂停。当前三场核查未覆盖硬暂停或技术暂停恢复，必须补充样本；未验证的情况输出未知。

验收：长冻结后 live 从接近 0 开始；暂停与恢复不跳时或重复扣时；下包、开始／取消拆包分别更新对应计时。

## 3. 阵容与字段完整性

维护本回合参赛阵容与每人状态，分开表达生死、装备、位置和字段是否已知。

- 死亡已确认而 Pawn 消失：保留阵容和已知死亡状态，不要求死者位置。
- Pawn 消失且生死不明：标记未知，不能默认死亡。
- 存活已知但坐标缺失：存活统计可用，空间特征缺失。
- 经济／装备字段不可读：不能用 0 假装确实没有资源。
- 已确认且未变化的装备允许延续；上次变化时间不等于上次观测时间。
- 换边、重开、回合切换按字段规则清理历史，防止错误继承。

分别输出阵容识别、生死、存活位置与装备覆盖率。分母应来自确认的阵容或存活状态，不能只统计已经出现在快照里的玩家。当前战斗资源聚合存活玩家，全队资金如包含死者则明确命名。

样本按质量分为可用、部分缺失、不可用。是否保留仅依据当时状态和统一契约；事后按阶段与胜负报告剔除比例，检查选择偏差，不能为了改善分数按标签删样本。

## 4. 测试与重新导出

| 场景 | 验收 |
|---|---|
| 热身到正式比赛 | 不把热身 freeze-end 算成正式开局 |
| 普通回合切换与真正重开 | 正式编号正确，尝试 ID 不冲突，作废记录不混入 |
| 半场与加时 | 阵营、编号、规则和历史正确衔接 |
| 长冻结、暂停与恢复 | 时间连续且不计入错误的等待时长 |
| 下包、拆包与取消 | 阶段及双计时独立正确 |
| 死亡、实体缺失与掉线 | 已知死亡与未知状态区分 |
| 改动未来事件 | 历史输入特征不变 |
| 前缀解析与完整解析 | 截断点之前的特征一致 |

先用纯状态转换测试和真实 Demo 轨迹回归，再从原始 68 场 Demo 重建独立 v4 数据。旧 JSONL 未保留足够的事件证据，不能只替换字段修复。

导出数据清单、每场质量报告和新旧差异报告，记录源文件哈希、解析器／特征版本、参数、回合增删与样本剔除原因。唯一键使用 (matchId, roundId, tick)。筛选后重新计算回合内 sampleWeight，保留回合权重和为 1。

## 5. 模型比较与发布

沿用 [68 场实验](training-report-68-matches.md) 的 63/5 比赛名单，继续比较逻辑回归和 LightGBM，不在语义迁移时同时扩大模型路线。

1. 保存 v3 模型在原验证集上的基准。
2. 按原 Demo 身份和 tick 对齐新旧共有有效样本，使用相同权重比较 v3/v4；不能按已被修正的旧回合号对齐。
3. 单独报告 v4 在全部有效验证样本上的结果和覆盖率，避免通过剔除困难样本制造提升。
4. 以 Log Loss、Brier 为主，同时检查开局、5v5、残局和 post-plant。特征消融与选择在训练比赛内部进行。
5. 原 5 场已被查看，作为迁移回归集；最终泛化判断还需新比赛或时间后移测试。

修正数据不等于自动发布模型。新模型须绑定 schema、特征清单、数据版本与评估报告；v3 模型不得接收 v4 特征。

## 6. 保留与回滚

- 保留 datasets/mirage-68-local-v3.jsonl 及整个 models/win-baseline-v3-holdout-68-5，不直接覆盖。
- 实施迁移前后记录现有工件哈希；v4 使用独立新目录，目标存在时拒绝覆盖。
- 当前导出器已拒绝覆盖已有数据文件，但训练脚本仍会写入同名工件；执行新训练前必须选择全新输出目录。
- 原始 Demo、JSONL 和二进制模型继续由 .gitignore 排除；GitHub 只保存代码、方案和评估说明。
- 训练 schema 与回放窗口 schema 分别版本化，不能通过改文件名伪装语义升级。

本阶段完成标准：异常有归因、状态定义一致、历史特征不含未来信息、数据变化可追溯、新模型可复现并有明确替换依据。实时接入与胜率页面不属于本阶段交付。
